# CLAUDE.md

Repository-local instructions for the q2-confluence plugin (registered name `confluence`, module `q2_confluence`); the global `~/.claude/CLAUDE.md` also applies.
The plugin is a nested repository inside the thermo-hec project, whose `CLAUDE.md` and memory hold the project context; git commands here use `git -C q2-confluence` from the project directory.

## Conventions set in review (developer, 2026-10-13)

 * Only registered actions are public functions; every other function, including usage-example functions, fixture factories, nested helpers and test helpers, starts with an underscore.
 * Every function body opens with `# TODO: this is AI-generated code; human review pending`, and every registered action's description ends with `EXPERIMENTAL: this is AI-generated code; human review pending.`; the developer deletes both as functions pass review. New functions and actions get the same markers.
 * An output name never repeats an input or parameter name: q2cli classifies signature entries by name and renders such an output as a second `--i-` option. Follow the stock convention of descriptive output names (`relative_frequency_table`, `collapsed_tree`, `integrated_metadata`); `tests/test_plugin_setup.py` enforces it. Render `qiime confluence <action> --help` for every action whose signature changes.
 * Metadata and TSV column names use hyphens (`original-sample-id`, `study-id`); action, parameter and output identifiers stay Python identifiers. `sample-id` is a reserved metadata ID header and cannot be a column name (query-reads uses `sample`).
 * Merged sample IDs are `<id>-<key>` with `original-sample-id` and `study-id` columns (`source` until 2026-10-16, `profile-type` until 2026-10-23); pairing relies on identical original IDs across sources.
 * Provisional actions name their intended home in their description (q2-feature-table, q2-phylogeny, q2-types); the `deprecated` flag was dropped on 2026-10-28 for the alpha note at the top of the README (the README was cut to a minimum the same day: title, warning, one paragraph, the tutorial link, an "AI disclosure" section with the review status as of a date and a GitHub code search for the marker comment, to keep current; the action table lives in the parent project's WORKFLOW.md and in `git show b2d44e5:README.md`).
 * Edit upstream reference data as little as possible (developer, 2026-10-21): the GTDB tree and taxonomy are imported as they are, `gtdb-tree-collapse` shears at the ancestor without changing branch lengths and keeps GTDB's internal labels, the GTDB root is documented with a Note annotation rather than re-rooted, and reference artifacts are fetched from their sources, never repackaged. The less an upstream resource is modified, the less can go wrong and the less there is to maintain; prefer documenting a property over changing it.
 * `integrate` (since 2026-10-23) takes tables, tree and metadata only: each source is filtered to the tree's tips with `phylogeny filter-table` (counts per source in the integrated metadata, a `RachisWarning` past `DROPPED_SHARE_WARNING`), the metadata collection is keyed like the tables and each study's IDs are suffixed with its key before the stock `metadata merge`, and the taxonomy is GTDB's own artifact used directly downstream. Trees reach the plugin through `GTDBNewickFormat`, whose transformer drops the root label and quotes every bare label with an underscore, so every action views trees as `skbio.TreeNode`; no raw Newick read remains.
 * Stock actions over custom code; one concern per function and per commit; no rerun-only modes. Every action keeps one usage example, and `tests/test_examples.py` executes them all.
 * The workflow runs on proportions: no counts conversion and no rarefaction anywhere (the `frequency` action was dropped on 2026-10-13); `relative-frequency` renormalizes after feature filters, and the paired report computes its distances once on the relative table.
 * The metagenome profile comes from the `sylph` plugin (sibling repository `mosh-sylph/`, its own session; read it, file findings, never edit it). The sylph actions, types and fixture this plugin carried left on 2026-10-16; the tutorial needs both plugins installed (`pip install -e ../mosh-sylph` into this environment until mosh-sylph is published).
 * Commit messages name @gregcaporaso as the reviewer who requested the change and say what Claude implemented, with the `Co-Authored-By` trailer; never push.

## Environment and checks

 * Commands in documentation are split one parameter per line with `\` continuations, as in the tutorial, and environments are named by creation date (`q2-confluence-dev-$(date "+%Y-%m-%d")`); both are the developer's conventions (2026-10-19).
 * Environments since 2026-10-28 (release day): the base is the qiime2 distribution's released 2026.10 environment, created as https://install.qiime2.org says (`rachis-qiime2-2026.10`; `CONDA_SUBDIR=osx-64` under Rosetta on Apple Silicon), plus `environment-files/q2-confluence-dev-extras.yml` with `conda env update`, then `make dev` (this plugin editable; mosh-sylph's extras file adds sylph for the tutorial) and `qiime dev refresh-cache`; CI builds the same way. The local env of that kind is the developer's to create; until then the review session used `q2-confluence-dev-2026-10-23` (`/opt/homebrew/Caskroom/miniforge/base/envs/q2-confluence-dev-2026-10-23`, rachis 2026.10.0.dev0+8, both plugins editable, no `sylph` binary until mosh-sylph's extras are applied). Use an env without activation: `PATH=$D/bin:$PATH CONDA_PREFIX=$D MPLCONFIGDIR=$TMPDIR/mpl NUMBA_CACHE_DIR=$TMPDIR/numba`. In 2026.10 the CLI package is `rachis_cli` and the framework `rachis` (the `qiime2` alias may or may not exist; check before relying on it).
 * The q2cli cache under that env is read-only in the sandbox: for `qiime ... --help` and `qiime dev refresh-cache`, unset `CONDA_PREFIX` and set `HOME=$TMPDIR/home`; q2cli then caches under that HOME.
 * Before every commit: `flake8`, `q2lint`, `python -m pytest -q` (about five minutes; run only the affected test module while iterating). Run the full suite in the background and do not edit files while it runs.
 * `sed -i ''` on macOS has no `\b`; use Python for word-boundary edits. Tokenize-based renames shift continuation-line indents (flake8 E128); check them.
 * q2cli does not create missing output directories; a page or script must `mkdir` them.

## Ownership

 * This repository has no docs site (removed 2026-10-16): the tutorial, its data-preparation page and the ReadTheDocs build live in the sibling repository `thermo-hec-tutorial/` (its own session), which pins this plugin by commit in its extras file. A change to an action's name, signature or output here means updating that page and its pin, and re-rendering its describe-usage blocks.
 * Code, tests, examples, action help text and `README.md` are Claude's to keep accurate in the same commit as the change they describe.
 * The thermo-hec project's `slurm/tutorial.sbatch` renders the tutorial page to CLI commands with rachis_cli's usage driver and runs them on bacon with both plugins installed; a change to an action's CLI is tested there (re-ship the plugin as a `git archive` tarball at the commit under test).
